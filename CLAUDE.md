# Working in this repository

## Navigate and change code through the code graph

`mlx-out/bin/mlx-codemap` (tools/codemap, Observatory's index) knows every
declaration and every use in the repository's Mlx code: files, symbols,
references, callers and callees, imports, layers, sizes, hot spots, memory
and crashes. Use it for all development, not only for debugging: before
reading a file to find something, before changing a function, before
renaming or deleting, and to check what a change touches.

- Find a symbol: `mlx-codemap find NAME`; its source: `mlx-codemap show SYMBOL`
  (qualify it as `path:name` when a name exists twice, e.g.
  `compiler/cc/scope.mlx:findKind`); the definition at a place:
  `mlx-codemap def FILE:LINE:COL`.
- Who uses it, and what it uses: `refs SYMBOL`, `callers SYMBOL`,
  `callees SYMBOL`, `members SYMBOL`; files: `imports FILE`,
  `importers FILE`, `outline FILE`.
- Before a change, the impact: `callers`/`refs` of what changes;
  after it: `unresolved FILE`, `layers` (the import rules in
  codemap.layers), `cycles`, `diff [BASE]`.
- Structure and quality: `unused`, `copies`, `complex`, `sizes`, `risky`,
  `workarounds` (raw page allocators, hand-written tables and arrays),
  `untested`, `reach PROGRAM`, `rewrite PATTERN --apply`.
- Run time: `hot` (with mlx-out/bin/mlx-profile's profiles), `memory
  PROGRAM` (with MLX_LEAK_CHECK=1), `frames`, `crashes` (std.crash's
  reports, C and C++ frames named and demangled).

grep is for text that is not code (logs, generated output, C/C++ sources
the graph does not cover yet). Do not hunt through Mlx code with grep when
the graph answers the question.

## Diagnose with the repository's own tools

- Crashes: the program's crash report (std.crash; mlxlibc programs install
  it too) names the function, the call chain and file:line; `mlx-codemap
  crashes` lists them by function. If a report lacks something, improve the
  report, do not fall back to gdb.
- Profiles: `mlx-out/bin/mlx-profile [-o DIR] PROGRAM ARGS`, then
  `mlx-codemap hot`.
- Memory: `MLX_LEAK_CHECK=1 PROGRAM`, then `mlx-codemap memory PROGRAM`;
  mlx-cc's arena: `MLX_CC_STATS=1`.

## The toolchain is ours

Mlx (mlx4), mlx-cc, mlx-ld, mlx-ar, mlx-cheaders, mlxlibc, mlxlibcpp and
std.build (`./mlx build`). No third-party compilers, linkers or C
libraries in what is built; C headers are generated by mlx-cheaders from
Mlx modules, never written by hand. WebKit (projects/webkit) is never
modified: the port is our own files (see projects/webkit/PORT.md).
